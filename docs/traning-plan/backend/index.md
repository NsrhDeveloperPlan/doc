# 后端开发学习路线

当博客需要在线读取、保存文章并验证博主身份时，浏览器负责把页面画出来，**后端**（Backend）负责处理这些数据与业务逻辑。纯静态博客也可以直接读取项目里的文件，不是每个博客都必须配后端；本路线练习的是为博客提供在线服务的那一部分。

我们用最不绕弯子（感觉瞬间豆姐俯身了）博客读写过程来理解，后端每天干的就是这几件事：

1. **接收请求（Request）**：浏览器或客户端向后端发消息，比如“请给我第 1 页的文章列表”或“我要新建一篇文章”。
2. **处理业务与读写数据库（Database）**：后端程序检查请求合不合理（比如标题有没有漏填、有没有权限发布），然后去数据库里查询或保存数据。
3. **返回响应（Response）**：后端把处理结果打包成通用的结构化文本（最常见的就是 **JSON** 格式），连同状态码一起发回给请求方。客户端拿到这份 JSON，再决定怎么展示给用户。
4. **提供接口（API）**：上面这一问一答的约定规则——访问哪个地址、传什么参数、返回什么格式的 JSON——就叫做后端对外提供的**接口**。

学习后端**不需要先学完前端**。没有现成的网页配合时，我们会使用专门的接口调试工具（如 Apifox、Bruno 或 Postman）直接向你的后端程序发请求、看返回的 JSON 结果。如果你还没了解过整体培训规则，可以先阅读 [学习计划与方向选择](../index.md)。确定走后端方向后，把本页存进浏览器书签即可。

## 为什么围绕同一个“Blog API”迭代半年

很多初学者学后端容易写成一堆互不相关的代码片段：今天写个计算器，明天连一下数据库，后天试一下登录，最后还是不知道一个完整的后端服务长什么样。

在这条路线里，我们从头到尾只维护一个核心项目：**博客后端 API（Blog API）**。

这个服务对应的就是 [前端开发学习路线](../frontend/index.md) 里那个个人博客的数据后台。但我们同样不靠堆砌花哨功能来凑工作量——不做评论区、不做点赞、不接支付、也不拆微服务。24 周的主线非常纯粹：

**跑通最小 HTTP 服务 → 实现文章与标签的增删改查接口 → 接入 SQL 数据库实现持久化 → 加上博主登录鉴权、缓存与限流 → 用 Docker 打包并完成自动化部署。**

你会在这个过程中自然体会到真实后端的核心矛盾：比如**公开读取与受控写入的区分**——任何访客都可以免登录读取文章列表和文章内容，但新建、修改、删除文章的接口必须验证博主身份；又比如数据怎么从“程序一关就全丢的内存变量”一步步变成“有关系约束、可迁移、带缓存的可靠存储”。

## 三个技术栈分支怎么选

后端的四个阶段与每周业务目标完全统一，但提供 **Go + Gin**、**Python + FastAPI** 和 **Java + Spring Boot** 三个技术栈分支。

**你只需要从中任选一栈走完 24 周，不要同时学两三个。** 后端的核心功底在于接口契约、数据表设计、权限控制和工程交付，这些思路在三个栈里完全相通。

| 对比维度 | Go + Gin | Python + FastAPI | Java + Spring Boot |
| :--- | :--- | :--- | :--- |
| **语言准备与特点** | 静态类型，通常编译为可执行文件，需要先理解切片、映射、结构体和错误处理 | 通过缩进组织代码，可用类型提示描述数据结构；需要先掌握函数、集合与基本类型 | 静态类型，常用类、接口与泛型组织程序，可与 MC 模组方向共用语言基础 |
| **编程体验** | 使用 Gin 定义路由与中间件，在代码中显式检查和处理错误 | FastAPI 借助 Pydantic 校验输入，并根据接口声明生成 OpenAPI 与交互式文档 | 使用 Spring Boot 的注解与依赖注入组织代码，逐步学习控制器、业务与数据访问分层 |
| **本课程常用工具** | Gin、原生 `database/sql` 与 GORM（或 sqlc）、JWT、Redis 客户端 | FastAPI、Pydantic、SQLModel / SQLAlchemy、Alembic（极简场景会顺带对比 Flask） | Spring Boot Web、JPA 或 MyBatis-Plus、Spring Security、Flyway |
| **适合的兴趣方向** | 喜欢代码直接、编译部署简单，对云原生或网络服务感兴趣 | 喜欢快速验证想法，或未来打算接触数据处理、AI 接口编排 | 倾向系统化学习经典企业级后端架构，或计划与 Minecraft 模组方向衔接 |

::: tip 关于技术栈选择的提醒
1. **关于 Python 分支里的 Flask**：当需求真的只有一两个简单接口时，单个文件的 Flask 非常轻便；但涉及到参数校验与自动生成接口文档，FastAPI 省事得多。因此 Python 分支以 FastAPI 为主线，Flask 仅作为极简场景的对比补充，不单列第四条路线。
2. **选栈不能代替语言基础**：选哪个分支取决于你的兴趣和已有基础，任何框架都没法让你跳过编程语言本身去写业务。不必纠结“哪个栈性能天下第一”或轻信“一天速成某语言”，把其中一个扎实用在项目里跑满 24 周，比跟着排行榜反复横跳有用得多。
:::

## 语言前置要求与真实时间账

本路线包含 **24 个核心学习周 + 2 个缓冲周（第 12 周后与第 18 周后）**，每周通常需要投入 **5～7 小时**。

需要特别说明的是：**这 24 周是从“用框架写第一个 HTTP 接口”开始的，默认你已经具备所选语言的基础语法。** 我们不会把一整门编程语言的语法硬塞进第 1 周让你边学框架边补课。

### 进入第 1 周前的语言自查清单

无论你选 Go、Python 还是 Java，在正式开启后端第 1 周之前，请确认自己已经能用这门语言做到以下五件事（不需要精通整套标准库或高级特性）：

- [ ] 能在自己电脑上独立编写、运行一个简单的命令行程序。
- [ ] 理解变量、基本数据类型、条件判断（`if/else`）和循环（`for`）。
- [ ] 会定义和调用函数（或方法），理解参数传递与返回值。
- [ ] 会使用该语言最常用的集合与复合结构（如 Go 的切片 `slice`、映射 `map` 与结构体 `struct`；Python 的列表 `list`、字典 `dict` 与类；Java 的 `List`、`Map` 与类/对象）。
- [ ] 看到编译器或解释器报出的基础错误（如拼写错误、类型不匹配、空指针/空值引用）时，能根据行号找到出错的代码位置。

如果你目前完全没有编程基础，请先跟着所选语言的基础教程把上面这五件事练熟，再进入后端第 1 周。v3 对 Java 分支给出的语言准备估计是额外约 **4～6 周**，不是三门语言统一适用的期限；实际时间要根据你的基础和每周投入调整，以自查清单为准。

### Java 后端与 Minecraft 模组的复用说明

如果你选的是 **Java + Spring Boot**，或者同时对 [Minecraft 模组开发学习路线](../minecraft/index.md) 感兴趣，这两条路线可以共用同一套 Java 语言与开发工具基础（JDK、IntelliJ IDEA、面向对象、集合与泛型、依赖管理、Git 与报错堆栈阅读）。

但要算清楚真实的时间账：主要节省的是重复学习语言与工具的时间。模组的游戏方块、渲染、数据生成和生物 AI，与后端的 HTTP、SQL、鉴权和容器部署仍需分别学习；读报错、组织代码和测试等经验可以继续复用。

如果你打算把两边都学完，可行的排布是：先走 MC 模组方向的第 1～6 周把 Java 基础打牢 → 转过来走完后端 24 个学习周 → 最后再回去走模组方向的第 7～24 周。单是课程就有 **6 + 24 + 18 = 48 个学习周**，还要另加缓冲周与复习衔接时间；按每周 5～7 小时的节奏，不应把两条完整路线理解为半年内可以完成的任务。

## 四个阶段与 24 周任务索引

原版学习大纲给出了后端四个阶段的目标与三栈对照，**下面的 24 周任务表是我们根据四阶段目标细化出的逐周教学安排**。每周三个技术栈共享同一个业务目标，具体实现按你所选的分支推进。每周的独立教程发布后，可从侧边栏或本页直接进入。

::: tip 表格与接口路径怎么读
手机上可以在表格区域左右滑动。尚未发布的周次只展示安排，不提供空链接。

表中的 `/posts/:slug` 表示按文章标识查详情，`:slug` 是占位写法，不是让你把冒号原样填进请求地址。不同框架的路由声明语法不同，实际请求会换成具体文章标识，详细契约随对应教程说明。
:::

### 第一阶段：HTTP 与 REST 基础（第 1～6 周）

第一阶段先不碰数据库，数据暂时存放在程序的内存变量里（这意味着每次重启服务，刚才新增的数据就会恢复原状——这是本阶段的正常预期）。

这样安排是为了让你先集中精力搞懂一件事：**一个规范的后端接口是怎么接收请求、校验数据、处理错误并返回 JSON 的。** 你会从最简单的 `/health` 健康检查接口起步，用接口调试工具发出第一条请求，逐步做出文章与标签的增删改查（CRUD），并整理出第一份标准的 OpenAPI 接口文档。

各栈在本阶段主要接触 Web 框架与基础校验工具：Go 使用 **Gin**；Python 使用 **FastAPI** 与 **Pydantic**；Java 使用 **Spring Boot Web** 与参数校验注解。注意，本阶段写出的新建、修改、删除接口还没有加登录保护，仅供你在自己电脑上调试学习，不要直接暴露到公网上。另外，从第 1 周起我们就会配合调试工具或基础测试脚本验证每个接口的正常与异常返回，而不是把测试全部攒到半年后。

| 周次 | 本周主题 | 本周可验证成果 |
| :--- | :--- | :--- |
| [第 1 周](./week-01.md) | 环境准备与最小服务 | **v0.1 最小健康检查服务**：确认所选语言环境可用，启动本地服务并提供 `GET /health` 接口，用接口调试工具看到返回的 JSON，完成首次本地 Git 提交 |
| 第 2 周 | 请求、响应与路由设计 | **v0.2 内存版文章只读接口**：理解 HTTP 方法、路径参数、查询参数与状态码，基于内存数据实现 `GET /posts`（文章列表）与 `GET /posts/:slug`（单篇文章详情） |
| 第 3 周 | 文章增删改接口（CRUD） | **v0.3 文章写操作闭环**：实现新建（`POST`）、修改（`PUT/PATCH`）与删除（`DELETE`）文章接口，通过调试工具连续调用并观察内存列表的变化 |
| 第 4 周 | 参数校验与统一错误处理 | **v0.4 健壮的输入校验与错误响应**：拦截缺必填字段、格式非法等请求并返回 `400`，查询不存在的文章返回 `404`，统一全站错误 JSON 结构 |
| 第 5 周 | 标签接口与代码模块拆分 | **v0.5 标签接口与目录重构**：实现 `GET /tags` 及文章与标签的基础关联读取，将单文件代码按路由、业务处理与数据模型拆分目录 |
| 第 6 周 | 接口契约与阶段验收 | **v1.0 OpenAPI 接口文档与阶段自测**：生成或整理 OpenAPI 接口文档（锁定 `GET /posts`、`GET /posts/:slug`、`GET /tags`、`POST /posts` 等核心契约），完整回归验证正常与错误场景 |

表中的错误状态码是课程要落实的接口约定，不代表框架默认行为已经一致。例如 FastAPI 默认的请求校验错误通常返回 `422`；如果课程统一约定为 `400`，会在第 4 周明确配置与测试，不能只改文档里的数字。可参考 [FastAPI 官方错误处理说明](https://fastapi.tiangolo.com/zh/tutorial/handling-errors/)。

### 第二阶段：SQL 与持久化（第 7～12 周）

第一阶段结束时，服务一重启文章就清空了。第二阶段专门解决“数据持久化”问题，把内存变量替换成真正的 **SQL 关系型数据库**（如 PostgreSQL 或 MySQL，本地练习初期也可配合轻量数据库）。

我们不会一上来就让你用框架把 SQL 藏起来，而是先花两周亲手写基础 SQL 语句：建表、增删改查、处理“一篇文章有多个标签、一个标签下有多篇文章”的多对多关联（`JOIN`），并认识数据库索引的作用。理解底层 SQL 在干什么之后，再接入各自技术栈的数据访问工具（Go 使用原生 `database/sql` 与 **GORM** 或 `sqlc`；Python 使用 **SQLModel** 或 **SQLAlchemy**；Java 使用 **Spring Data JPA** 或 **MyBatis-Plus**），完成分页、关键字检索，并用数据库迁移工具把表结构变更管起来。

| 周次 | 本周主题 | 本周可验证成果 |
| :--- | :--- | :--- |
| 第 7 周 | SQL 入门与单表操作 | **v1.1 文章表结构与基础 SQL**：设计 `posts` 表，脱离业务代码直接编写并执行建表、插入、查询、更新、删除 SQL 语句 |
| 第 8 周 | 多表关系、关联查询与索引初识 | **v1.2 标签表与多对多关联查询**：设计 `tags` 表与文章—标签中间表，手写 `JOIN` 查询某标签下的文章列表，为高频查询字段建立基础索引 |
| 第 9 周 | 程序连接数据库与数据访问层 | **v1.3 接入数据库连接与 ORM/数据工具**：在后端工程中配置数据库连接，用所选栈的数据访问方式跑通单表的读写操作 |
| 第 10 周 | 用数据库全面替换内存存储 | **v1.4 持久化版文章与标签接口**：将第一阶段的全部接口底层切换为数据库读写，重启后端服务后验证原有文章与标签数据不丢失 |
| 第 11 周 | 分页查询与关键字检索 | **v1.5 列表分页、标签筛选与搜索**：为 `GET /posts` 增加分页参数、按标签过滤（`?tag=`）及标题关键字检索，验证边界页码与空结果表现（注：普通模糊查询未必能命中索引，重在跑通检索逻辑） |
| 第 12 周 | 数据库迁移与阶段回归验证 | **v2.0 可复现的数据库迁移**：引入迁移工具（如 `golang-migrate`/`goose`、`Alembic` 或 `Flyway`）管理建表脚本，在空库上自动初始化表结构并通过全部接口契约验证 |

::: tip 缓冲周 A（第 12 周后）
用一周时间消化前两个阶段的内容。如果前面有欠下的必做任务或还没调通的 SQL 查询，先在这周补齐；如果进度顺利，请检查一遍所有接口的返回格式是否与第 6 周定下的契约一致，并清理代码中残留的内存假数据逻辑。
:::

### 第三阶段：鉴权、缓存与安全（第 13～18 周）

现在数据能持久保存了，但写接口还没有验证调用者身份。如果把这样的服务公开，其他能够访问服务的人也可能调用文章新建、修改或删除接口。因此前两阶段先在本机练习，公开部署前要补齐本阶段的鉴权。

第三阶段的核心任务是**给服务加上安全边界与性能保护**。你会先实现博主账号的密码哈希存储（严禁在数据库里存明文密码），然后选择一种主流鉴权方式（JWT 令牌或服务端 Session，掌握透彻其中一种即可，不必同时堆砌两套）实现登录与身份校验，做到“读接口全员公开，写接口必须持有效身份访问”。随后接入 **Redis** 缓存热门列表数据、处理更新文章时的缓存失效，加上基础的接口请求限流，并把自动化接口测试系统地补齐。

| 周次 | 本周主题 | 本周可验证成果 |
| :--- | :--- | :--- |
| 第 13 周 | 账号模型与密码安全哈希 | **v2.1 博主账号与密码哈希存储**：使用适合密码存储的 `bcrypt` 或 `argon2` 实现，创建博主用户表并初始化账号，验证数据库中只保存密码哈希而非明文；哈希不是可解密还原的加密 |
| 第 14 周 | 登录接口与身份状态管理 | **v2.2 登录与身份凭证签发**：选定 JWT 或 Session 方案实现 `POST /login`，验证密码正确时签发凭证、密码错误或凭证过期时返回 `401` |
| 第 15 周 | 读写权限分离与鉴权中间件 | **v2.3 受保护的写接口**：编写鉴权中间件/过滤器，公开读取文章和标签，要求有效博主身份才能执行文章与标签的写操作；同时核对 `POST`、`PUT/PATCH`、`DELETE`，不把所有 `GET` 路由一概放行 |
| 第 16 周 | Redis 缓存与失效处理 | **v2.4 文章列表缓存**：接入本地 Redis 缓存文章列表，在新建、修改或删除文章时清理或更新受影响的缓存，并验证失效后能读到新数据；不额外引入阅读计数功能 |
| 第 17 周 | 接口限流与安全异常处理 | **v2.5 基础防刷限流**：为登录与高频接口配置按 IP 或时间窗口的请求速率限制，连续快速请求时验证触发 `429 Too Many Requests` 并在冷却后恢复 |
| 第 18 周 | 接口自动化回归测试 | **v3.0 自动化测试套件**：使用本栈测试工具（`httptest`、`pytest + httpx` 或 `MockMvc`）编写自动化测试，覆盖公开读取、登录鉴权拦截、文章写入及缓存更新等关键链路 |

::: tip 缓冲周 B（第 18 周后）
进入最后的部署阶段前，跑一遍自动化测试，确保已有用例通过。同时检查项目里是否有把数据库密码、JWT 密钥直接写死在代码里的情况。敏感值通过运行环境注入，或放进不提交的本地配置文件；含有秘密的配置文件加入 `.gitignore`，仓库只保留不含秘密值的配置模板。
:::

### 第四阶段：容器化与工程交付（第 19～24 周）

代码在你自己电脑上跑通还不够，因为你的电脑上装了语言环境、数据库和 Redis，换一台新机器重新配一遍环境非常容易出错。

最后六周解决“怎么把服务干干净净地打包交付出去”。你会使用 **Docker** 把后端程序打包成标准镜像，再用 **Docker Compose** 一键同时拉起后端服务、数据库和 Redis。第 21 周进行接口联调验证，随后配置 **GitHub Actions** 实现提交代码时自动跑测试与构建，补充运行日志与排错演练，最终整理出完整的项目文档与演示环境（v4.0）。

| 周次 | 本周主题 | 本周可验证成果 |
| :--- | :--- | :--- |
| 第 19 周 | Docker 容器化打包 | **v3.1 服务镜像构建**：编写 `Dockerfile`（理解构建与运行环境分离），将 Blog API 打包为 Docker 镜像并通过环境变量注入配置独立运行 |
| 第 20 周 | Docker Compose 多容器编排 | **v3.2 一键启动完整环境**：编写 `compose.yaml`，统一编排后端服务、数据库与 Redis，配置数据库数据卷并验证重建容器后数据仍在；删除数据卷会丢失其中数据，不能把数据卷当成备份 |
| 第 21 周 | 接口联调与跨域（CORS）验证 | **v3.3 接口契约联调**：有前端博客时，将其本地 JSON 读取切换为真实接口，并在浏览器验证需要的跨域规则；没有前端时，用调试工具或自动化客户端验证接口流程，浏览器跨域另行验证。写接口仍可使用调试工具，不要求扩展前端为管理后台 |
| 第 22 周 | CI/CD 自动化流水线 | **v3.4 自动测试与构建流水线**：配置 GitHub Actions，每次推送代码时自动执行代码检查、运行测试套件并验证 Docker 镜像构建（敏感凭据通过 Secrets 管理，严禁写进仓库） |
| 第 23 周 | 结构化日志、健康检查与排错 | **v3.5 运行排错记录**：补充请求耗时与错误日志，避免输出密码和凭证；区分服务进程存活与数据库等依赖就绪，保留 `/health` 的存活语义并补充依赖就绪检查，模拟并记录端口冲突、数据库连接失败等故障 |
| 第 24 周 | 项目收官与交付文档 | **v4.0 正式收官交付**：完善项目 `README.md`，包含架构说明、表结构设计、OpenAPI 文档入口、一键启动步骤与 24 周迭代记录，完成本地或云端演示验证 |

::: tip 关于联调与部署的边界
接口调试工具请求成功，不能证明浏览器跨域一定正常，也不能替代真实页面操作验证。CORS 是浏览器参与执行的机制，详见 [MDN 的 CORS 说明](https://developer.mozilla.org/zh-CN/docs/Web/HTTP/Guides/CORS)。

学习阶段可以先完成本地 Docker Compose 交付演示，但本地运行通过不代表已经完成公网部署验收。计划公开上线时，再核对托管平台的费用、访问条件、HTTPS 与数据备份，以及目标地区和服务商的备案等要求。
:::

## 第 1 周你要做什么

在已经具备所选语言基础的前提下，第 1 周的任务非常轻量，目的是帮你把后端的开发、调试和存档链路跑通：

1. **确认本地开发环境**：检查你选定的语言环境（Go、Python 或 Java）及依赖管理工具在命令行下工作正常。
2. **启动最小 HTTP 服务**：新建 `blog-api` 项目文件夹，引入所选分支的 Web 框架（Gin、FastAPI 或 Spring Boot），写一个最简单的 `GET /health` 接口，让它在本地端口跑起来并返回一段表示服务正常的 JSON（例如 `{"status": "ok"}`）。
3. **用调试工具发出第一次请求**：打开接口调试工具（或浏览器/命令行），向本地的 `/health` 地址发送请求，亲眼看到状态码 `200` 和返回的 JSON 内容。
4. **完成第一次本地 Git 提交**：编写 `CHANGELOG.md` 记录 v0.1，使用 VS Code 左侧的「源代码管理」图形界面（或集成终端命令）初始化本地 Git 仓库并完成首次 commit。

和前端路线一样，第 1 周**不需要**你把代码推送到 GitHub，也不需要操作 Fork、Pull Request 或配置签名，先在本地把代码干净地管理起来即可。

[开始第 1 周：启动你的第一个后端服务](./week-01.md)。也可以从侧边栏直接进入。

## 开始前的环境准备

后端全周期涉及数据库、Redis、Docker 等不少工具，但**千万不要在第一周把它们一次性全装上**。数据库第 7 周才用，Redis 第 16 周才用，Docker 到第 19 周才登场，后续对应周次的教程会一步步带你安装和配置。

在开始第 1 周之前，你只需要准备好以下四样基础工具：

1. **你所选分支的语言运行环境**：
   - 选 **Go**：安装 Go SDK。
   - 选 **Python**：安装 Python 3 及包管理工具。
   - 选 **Java**：安装与所选 Spring Boot 版本兼容的 JDK，具体版本组合由第一周教程核对并说明，不要求现在自行追最新版。
2. **代码编辑器或 IDE**：Go 和 Python 推荐使用 **VS Code**（搭配对应语言的官方扩展）；Java 推荐使用 **IntelliJ IDEA**。
3. **接口调试工具**：从 Apifox、Bruno 或 Postman 中任选一款安装，用来给你的后端发请求。
4. **Git**：用于在本地记录每周的代码演进。

以上软件的官方网站入口与基础简介已汇总在 [软件资源](../software-resources.md) 页面（该页面仅提供官方下载入口与工具简介，具体配置与项目初始化步骤将在第 1 周教程中详细说明）。确认语言自查清单过关、装好这四样基础工具，就可以准备开启后端第 1 周的实践了。
