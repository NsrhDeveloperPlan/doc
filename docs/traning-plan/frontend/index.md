# 前端开发学习路线

## 小朋友你知道吗

我们平时用电脑或手机浏览网页时，看见的文章排版、导航菜单、按钮、切换明暗主题的动画，都属于前端开发的范畴。

本路线学习的是运行在用户**浏览器**（如 Chrome、Edge、Safari）里的 Web 前端，由三部分配合完成工作：

- **HTML** 负责搭架子，告诉浏览器“这里是文章标题，那里是一段正文，底下有一张图片”。
- **CSS** 负责外观与布局，它决定了字号多大、背景是什么颜色、卡片怎么并排摆放、在手机窄屏上怎么自动缩放。
- **JavaScript（简称 JS）** 负责逻辑与交互，比如点击按钮展开菜单、按年份把文章分组、或者从外部文件里把文章数据读取出来显示在页面上。

如果你还没了解过整体培训规则，可以先看一遍 [学习计划与方向选择](../index.md)。确定走前端路线后，把本页加入浏览器书签即可，后续每周更新的教程都会在这里汇总。

## 为什么要拿同一个“个人博客”练半年

很多新手学前端容易掉进两个坑：要么一上来直接背几十个标签和语法，背完也不知道怎么拼成网页；要么每学一个新工具就重开一个新项目，结果做了一堆半途而废的例子，哪个都拿不出手。

在这条路线里，我们只维护一个仓库：**个人博客（Personal Blog）**。

这个博客纯粹是用来练技术的素材☝️。我们判定你本周有没有学会的标准只有一个：**有没有把所学技术，在你的个人博客上实现出来**。

24 周对应 v0.1 到 v4.0 共 24 个版本，每一版都长在上一版的基础上：先手写 HTML 和 CSS 把静态页面搭出来并上线，接着用原生 JS 把写死的内容改成数据驱动，再把跑通的页面一步步搬进 Vue 或 React 框架，换上现成的组件库，最后补齐 TypeScript 类型、状态管理、自动化测试与构建部署。半年下来，你能直观地对比出每一阶段的新技术到底替你省掉了什么麻烦。

## 四个阶段与 24 周任务索引

下面按四个阶段列出全部 24 周的任务安排。每周的具体教程会作为独立文章陆续发布，发布后你可以直接从左侧边栏或本页进入。

### 第一阶段：手写 HTML + CSS，做出静态博客并上线（第 1～6 周）

你的任务是搞清楚网页的骨架怎么搭、样式怎么调。很多人在后面用框架调不出想要的布局，病根都在最基础的盒模型、Flexbox 和 Grid 没弄明白。

这一阶段会在本地从零写出首页、文章页、归档页和关于页，调整好配色、卡片布局和手机屏幕适配，并在第 6 周把博客真正部署到公网上。完成后，你手机连着网就能直接打开自己写的网站——这一版（v1.0）就是你后续所有改造的对照基线。

| 周次 | 本周主题 | 本周可验证成果 |
| :--- | :--- | :--- |
| [第 1 周](./week-01.md) | HTML 语义化骨架与首次 Git 提交 | **v0.1 纯 HTML 三页博客**：完成 `index.html`、`post.html`、`about.html`，页面间用超链接串起，完成首次 Git commit |
| 第 2 周 | CSS 基础语法与盒模型 | **v0.2 配上配色与卡片**：抽离 `style.css`，定好配色，将内容装进带圆角与阴影的卡片，统一标题与链接样式 |
| 第 3 周 | Flexbox 一维弹性布局 | **v0.3 导航栏与文章卡片**：顶部导航两端对齐，首页文章列表改为卡片排列，浏览器窗口变窄时自动换行 |
| 第 4 周 | CSS Grid 二维网格布局 | **v0.4 首页两栏与归档页网格**：首页改为“主内容 + 侧边栏”两栏结构，归档页排出网格卡片墙，重点文章跨两列展示 |
| 第 5 周 | 改造开源 CSS 组件与过渡动画 | **v0.5 引入并改造社区组件**：挑选 1～2 个开源按钮和卡片样式，删减到每行都能看懂后改为博客配色，加入悬停（hover）平滑过渡 |
| 第 6 周 | 响应式媒体查询与首次上线 | **v1.0 静态版正式上线**：用 `@media` 适配手机屏幕（导航纵向堆叠、两栏变单栏），推送到 GitHub 并完成线上部署，手机可直接访问 |

### 第二阶段：原生 JavaScript，把静态页面改成数据驱动（第 7～12 周）

第一阶段的静态版上线后，你会发现一个明显的痛点：每次想新写一篇文章，都要去复制粘贴一大段 HTML 标签，改起来极其费劲。

第二阶段就专门解决这个问题。你会用原生 JavaScript 把写死在 HTML 里的文章内容抽离出来，变成独立的数据文件（`posts.json`），再写代码把数据动态渲染成网页。同时，你会在这六周里练熟 DOM 操作、事件监听、数组处理（分组与分页）、异步请求（Fetch）以及代码分模块。到第 12 周结束时，你的博客外观和 v1.0 差不多，但底层已经完全变成由数据驱动的模块化结构（v2.0）。

| 周次 | 本周主题 | 本周可验证成果 |
| :--- | :--- | :--- |
| 第 7 周 | JS 变量、函数与 DOM 操作 | **v1.1 用 JS 渲染文章列表**：将文章信息整理为数组，用 JS 动态生成卡片插入首页，删掉原先手写的重复 HTML |
| 第 8 周 | 事件监听与 DOM 状态切换 | **v1.2 移动端菜单与锚点导航**：窄屏下点击汉堡按钮展开或收起菜单，点击导航链接平滑滚动到对应区域 |
| 第 9 周 | 数组高阶方法（map / filter / reduce / sort） | **v1.3 归档页按年份分组**：用数组方法将文章按年份自动归类、倒序排列并渲染，替换手写的归档页 |
| 第 10 周 | 日期处理、分页逻辑与 URL 参数 | **v1.4 文章分页**：首页每页展示 5 篇，支持上一页/下一页切换，当前页码同步写入 URL（如 `?page=2`），刷新不丢页码 |
| 第 11 周 | 异步编程与 Fetch API | **v1.5 独立 `posts.json` 数据源**：通过本地服务器异步请求 JSON 文件并渲染，补齐“载入中”状态与加载失败重试提示 |
| 第 12 周 | ES Modules 模块化重构 | **v2.0 模块化拆分**：将单文件 JS 按职责拆为 `data.js`（取数据）、`render.js`（渲染）、`ui.js`（交互）并在 `main.js` 组装，并在本周末选定下一阶段的框架 |

::: tip 缓冲周 A（第 12 周后）
进入框架阶段前，预留一周时间做整理。如果前 12 周有落下的必做任务，在这周补齐；如果进度正常，请把自己的 JS 代码从头通读一遍，确保没有糊里糊涂粘过来的代码，并选定接下来要用的前端框架（Vue 或 React），预习官方文档的前两节。
:::

### 第三阶段：逐页搬进 Vue / React 框架（第 13～18 周）

写完第 12 周的代码后，你会体会到手动创建 DOM 节点、手动拼装页面有多繁琐。第三阶段我们引入现代前端工程化工具（Vite + Tailwind CSS）和前端框架（Vue 或 React），解决组件复用与界面状态同步的问题。

注意，这一阶段是**给博客搬家**，而不是推倒重来。从第 13 周起，你会在 Git 里新建一个 `next` 分支，线上继续跑着稳定的 v2.0，你在新分支里把已经跑通的页面**一页一页**搬进框架工程：第 13 周只搬首页，第 14 周边搬其余页面边拆出可复用的组件，第 16 周全部搬完后再合并回主分支重新上线。

搬进框架不代表必须配后端服务器。整个第三阶段，博客依然是纯静态网站，继续读取本地的 `posts.json`。在此基础上，你还会用现成的开源组件库换掉手写样式，并用客户端路由实现无刷新的多页面切换（v3.0）。

| 周次 | 本周主题 | 本周可验证成果 |
| :--- | :--- | :--- |
| 第 13 周 | Vite 工程初始化与 Tailwind CSS | **v2.1 搭好脚手架并先搬首页**：新建 `next` 分支，创建 Vite 项目，接入 Tailwind CSS 与 Lucide 图标，先将首页搬进新工程 |
| 第 14 周 | 组件化拆分与 Props 传参 | **v2.2 边搬边拆组件**：搬入归档页与文章页，抽离 `NavBar`、`PostCard`、`PostList`、`Footer` 等组件，消除重复结构 |
| 第 15 周 | 响应式状态（State）驱动界面 | **v2.3 视图切换与排序**：用框架状态控制“卡片/列表”展示切换与“按时间/按标题”排序，不再手动操作 DOM |
| 第 16 周 | 生命周期与异步数据加载 | **v2.4 搬完最后一页并合并上线**：在组件挂载时异步加载 `posts.json`（含骨架屏与错误处理），合并 `next` 分支并构建部署 |
| 第 17 周 | 接入 UI 组件库美化 | **v2.5 组件库改造**：引入 Element Plus / Naive UI（Vue）或 shadcn/ui（React），替换手写的按钮、卡片、分页与导航，统一主题 |
| 第 18 周 | 客户端路由（SPA） | **v3.0 四页面单页应用**：配置首页、归档、文章详情（`/post/:id`）与关于页路由，实现无刷新切换及上一篇/下一篇跳转，解决线上刷新 404 问题 |

::: tip 缓冲周 B（第 18 周后）
做一次代码体检：删掉迁移过程中留下的废弃代码、统一变量与组件命名、把超过 200 行的臃肿组件拆小。你可以把 v1.0 到 v3.0 的页面截图放在一起对比，看看这 18 周手里的项目发生了什么变化。
:::

### 第四阶段：TypeScript、状态管理、数据层与工程交付（第 19～24 周）

最后六周不再大改页面外观，重点转向真实工程开发里的代码质量与交付链路：用 TypeScript 在写代码时提前拦住低级拼写与类型错误，用全局状态库管理跨页面数据，把数据请求单独抽象成一层，给核心逻辑补上自动化测试，并配置 GitHub Actions 实现每次推送代码后自动构建上线。

到第 24 周收官时（v4.0），你不仅有一个线上能访问的博客，仓库里还有完整的类型约束、单元测试、自动部署流水线，以及一份记录了 24 次演进过程的详细说明文档。

| 周次 | 本周主题 | 本周可验证成果 |
| :--- | :--- | :--- |
| 第 19 周 | TypeScript 类型约束 | **v3.1 全站 TypeScript 迁移**：定义 `Post`、`Tag` 数据结构与组件 Props 类型，逐步迁移脚本与组件逻辑；普通脚本使用 `.ts`，React 的 JSX 组件使用 `.tsx`，Vue 单文件组件保留 `.vue` 并在脚本中启用 TypeScript |
| 第 20 周 | 全局状态管理 | **v3.2 状态集中管理**：使用 Pinia（Vue）或 Zustand（React）集中管理文章数据、视图模式与菜单状态，实现必要的本地持久化 |
| 第 21 周 | 数据层抽象与切换真实接口 | **v3.3 独立 `api` 数据层**：抽离统一的数据请求出口；有后端或 Supabase 时切换为真实接口请求，无后端时保留本地 JSON 但完成接口层封装，页面组件无需改动 |
| 第 22 周 | 单元测试与组件测试 | **v3.4 自动化测试护航**：用 Vitest 为年份分组、分页、排序、日期格式化等纯函数编写单元测试，并为 `PostCard` 编写组件测试 |
| 第 23 周 | 生产构建优化与自动部署 | **v3.5 生产环境优化版**：配置路由懒加载与图片优化，配置 GitHub Actions 在 push 时自动构建部署，以 Lighthouse 性能评分达到 90 分及以上为目标，并记录测试环境与结果 |
| 第 24 周 | 项目收官与文档整理 | **v4.0 正式收官**：完善 `README.md`，包含 v1.0 与 v4.0 对比截图、架构说明、本地运行步骤及线上访问链接 |

## 两个常见疑问：选框架与接后端

在看任务表时，很多同学会对第 13 周的框架选择和第 21 周的后端接口心里没底，这里提前说明一下。

### Vue 和 React 选哪个？

**现在完全不用想这件事，到第 12 周末再做决定就行。**

前 12 周的 HTML、CSS 和原生 JS 是后续框架学习的共同地基。等你把第 12 周的模块化代码写完，再各看一遍 Vue 和 React 的官方入门示例，会更容易理解它们与手写页面的区别。本路线按两个分支安排相同的博客迭代目标，具体教程会陆续发布；你只需要二选一走到底，不要同时学两个：

| 对比维度 | Vue 路线 | React 路线 |
| :--- | :--- | :--- |
| **代码写法与上手体验** | 采用单文件组件（`.vue`），HTML 模板、样式和逻辑分区清晰，从手写 HTML 过渡过来非常顺畅 | 采用 JSX 语法，在 JavaScript 函数里直接写标签，完全用 JS 思维组织界面，习惯后非常灵活 |
| **配套生态与文档** | 官方直接维护路由（Vue Router）和状态库（Pinia），写法统一，中文文档与国内社区资料丰富 | 社区生态极其庞大，组件与工具选择多，本路线搭配 React Router 与轻量的 Zustand 状态库 |
| **本路线搭配组件库** | Element Plus 或 Naive UI | shadcn/ui |

无论选哪一个，核心都是“组件化”和“状态驱动视图”。把其中一个扎实用上 12 周，以后因为工作或项目需要去学另一个，这些经验能帮助你理解新框架，但具体 API 和生态仍需重新学习。如果到第 12 周末还是拿不定主意，挑一个看文档顺眼的直接开干即可。

### 没有后端怎么完成第 21 周？

前端路线全程可以独立走完，不依赖后端路线。

前期内容先写在 HTML 里，第 7 周开始整理为 JS 数组，到第 11 周才独立为项目中的 `posts.json`，之后继续使用这个本地数据源。到了第 21 周，教程的目标是让你学会**把“怎么拿数据”和“怎么画页面”彻底分开**（也就是抽离出一个专门的 `api.ts` 模块，或按项目实际情况整理已有的数据模块）。

- 如果你身边有结伴学后端的同学，或者你愿意花一点时间按文档配一个现成的云端数据库服务（Supabase），这一周就可以把数据源换成真正的网络接口。
- 如果你只专注于前端，完全不想碰后端或云服务，这一周你依然继续用本地的 `posts.json`，但要把散落在组件里的请求代码全部收拢到统一的数据层函数里，模拟真实接口的调用方式。只要做到了“以后换数据源时，页面组件一行代码都不用改”，第 21 周的教学目标就完整达成了。

## 第 1 周你要做什么

开启第 1 周时，你不需要懂任何配色、排版或编程逻辑，目标非常单纯：**做出 v0.1 版本的纯 HTML 三页博客，并完成第一次 Git 提交**。

在第一周的教程里，你会新建一个项目文件夹，亲手写出三个网页文件：

1. `index.html`（博客首页，放网站标题和几篇占位文章的列表）
2. `post.html`（文章详情页，放一篇示例文章的标题、日期和几段正文）
3. `about.html`（关于我页面，放一段简短的个人或站点介绍）

你会用 HTML 标签把标题、段落、列表标记清楚，用超链接（`<a>` 标签）把这三个页面互相连起来，做到在浏览器里点击导航就能在三页之间来回跳转。此时你还没有编写 CSS，页面使用浏览器的默认样式，外观朴素是正常的。最后，你会用 Git 把这三个文件提交到本地版本库，拍下项目的第一张“历史快照”。

[开始第 1 周：用 HTML 搭建三页博客](./week-01.md)。也可以从侧边栏直接进入。

## 开始前的环境准备

工欲善其事，但千万别在一开始装一堆根本用不上的工具。

整个前端路线遵循**用到什么装什么**的原则。本路线到第 13 周才引入 Node.js、Vite、Tailwind CSS，现在不需要为了第一周练习提前配置它们。电脑上已经安装过的工具也不用卸载。

在开始第 1 周之前，先准备好以下三样东西，安装和下载所需的时间会因网络与电脑环境而不同：

1. **现代浏览器**：推荐使用 Chrome 或 Edge。我们除了用它看网页，还会频繁用到它内置的“开发者工具（按 F12 打开）”来检查元素和排查错误。
2. **代码编辑器**：安装 **VS Code**，并在扩展商店里装上 **Live Server**（用于本地实时预览网页，第 11 周起的 Fetch 请求需要通过它或其他本地 HTTP 服务运行）和 **Prettier**（配置默认格式化工具并启用保存时格式化后，可以自动整理代码缩进）。具体配置会在教程中说明。<u>（特别地，如果你不习惯英文页面，那你可以看着教程先装一个中文插件）</u>
3. **Git 与代码托管账号**：在电脑上安装 **Git**，用来保存每周的本地提交记录；注册 GitHub 账号后，还可以推送到远程仓库。本路线第 6 周会讲解线上部署，可采用 GitHub Pages 等静态托管服务。

常用工具的官网入口和简要介绍已经整理在[软件资源](../software-resources.md)页面。具体安装、插件配置与验证步骤会在第一周教程中展开，先按需了解即可。
