# 第 1 周：用 HTML 搭建三页博客

这是 [前端开发学习路线](./index.md) 的第一周实践。本周我们要把你接下来半年持续维护的「个人博客」建立起来，做出它的第一个版本（`v0.1`）。

完成本周任务后，你的电脑里会有一个包含三个网页文件的文件夹：`index.html`（博客首页）、`post.html`（一篇完整的示例文章）和 `about.html`（关于页）。用浏览器打开这些文件，可以看到标题、段落和列表，在关于页还能看到一张本地图片，并且能点击顶部导航链接在三个页面之间来回切换。

因为本周不写 CSS 样式代码，也不碰 JavaScript，页面会使用浏览器的默认外观，通常是浅色背景、深色文字和带下划线的链接；已访问链接的颜色可能不同，浏览器设置也可能影响显示。觉得朴素是完全正常的，我们先把网页的骨架搭稳，第 2 周再专门用 CSS 给它换上配色与卡片外观。

<u>**注：同学们的作品不能和下面示例完全一样哦，那会视作无效的☝️**</u>

## 准备最少够用的工具

下面以 Windows 系统搭配 VS Code 和 Chrome/Edge 浏览器为例说明。如果你还没安装这些软件，可以在 [软件资源](../software-resources.md) 页面找到它们的官方网站入口，下载并按默认选项安装即可。

本周只需要准备好以下三样工具，不需要安装 Node.js、pnpm、数据库或 Docker，也暂时不需要注册 GitHub 账号或把代码传到网上：

1. **现代浏览器（Chrome 或 Edge）**：用来直接打开并查看你写的网页文件。
2. **代码编辑器（VS Code）**：用来编写代码。记事本也能改文字，但它不会给代码标颜色，也很容易漏掉符号。
   - **中文界面（按需安装）**：打开 VS Code 后，如果界面是英文且你希望改成中文，可以点击左侧边栏最下方的「扩展」图标（四个小方块，快捷键 `Ctrl + Shift + X`），在搜索框输入 `Chinese`，认准发布者为 **Microsoft** 的 `Chinese (Simplified) (简体中文) Language Pack for Visual Studio Code`，点击 Install 安装，然后按右下角提示重启 VS Code。
   - **辅助扩展（可选，非本周前提）**：你可以顺手在扩展面板搜索并安装 `Prettier - Code formatter`（代码排版格式化）和 `Live Server`（本地预览服务器）。注意，Prettier 安装后**不会**自动在保存时生效，需要在设置里额外指定默认格式化工具并勾选 `Format On Save`；即使完全不装这两个插件，也丝毫不影响完成本周的 HTML 练习，本周我们直接用浏览器打开网页文件即可。
3. **版本控制工具（Git）**：用来给你的代码拍“历史快照”。
   - 安装时一路保持默认选项即可。装好后，打开 VS Code，按快捷键 `` Ctrl + ` ``（数字键 1 左边那个带波浪号的键）呼出底部的「终端」面板，输入以下命令并回车：

```bash
git --version
```

如果终端打印出类似 `git version 2.x.x.windows.1` 的版本号，说明 Git 已经安装成功。如果提示“找不到命令”或“无法将 git 项识别为……”，请彻底关闭 VS Code 后重新打开再试一次。

## 建立你的博客项目文件夹

在开始写代码前，先分清楚两件事：你现在正在阅读的网站是培训文档站（你看到的是教程文件），而你接下来要动手写的是**属于你自己的独立练习项目**。不要去下载或修改培训文档站的仓库，你只需要在自己的电脑里新建一个干净的文件夹。

本周结束时，你的项目文件夹结构会长这样：

```text
personal-blog/
  index.html
  post.html
  about.html
  images/
    avatar.png
  CHANGELOG.md
```

请按以下步骤把这个文件夹建好：

### 1. 创建并打开文件夹

在电脑上找一个你容易找到的位置（比如桌面或 `D:\projects\`），新建一个普通文件夹，命名为 `personal-blog`（建议全用英文小写字母和连字符，不要用中文或空格）。

打开 VS Code，点击左上角菜单「文件 (File)」→「打开文件夹 (Open Folder...)」，选中刚才建好的 `personal-blog`。此时 VS Code 左侧的「资源管理器」面板里会显示 `PERSONAL-BLOG`，底下还是空的。

### 2. 开启 Windows 文件扩展名显示

文件名通常带有后缀（扩展名），帮助电脑识别文件类型：`.txt` 常用于纯文本，`.png` 是一种图片格式，`.html` 用于网页。扩展名是命名约定，改名并不能改变文件内容的实际格式。

Windows 默认会隐藏已知文件的扩展名。如果你直接右键新建一个“文本文档”并改名为 `index.html`，它真实的名字其实是 `index.html.txt`——双击打开时它还是个记事本文件，而不是网页。

为了避免踩这个坑，建议先在 Windows 文件资源管理器里把扩展名显示出来：
- **Windows 11**：打开任意文件夹，点击顶部菜单栏的「查看」→「显示」→ 勾选「文件扩展名」。
- **Windows 10**：打开任意文件夹，点击顶部切换栏的「查看」选项卡 → 勾选右侧的「文件扩展名」。

当然，最稳妥的做法是**直接在 VS Code 里新建文件**：把鼠标移到 VS Code 左侧面板的 `PERSONAL-BLOG` 标题行上，点击旁边出现的第一个小图标「新建文件 (New File)」，直接输入 `index.html` 并回车，这样创建出来的一定是真正的 `.html` 文件。

### 3. 准备一张本地头像或配图

博客的“关于”页面需要展示一张图片。

1. 在 VS Code 左侧面板点击第二个小图标「新建文件夹 (New Folder)」，输入 `images` 并回车。
2. 在电脑里找一张可以公开使用的普通图片（比如你的卡通头像、风景照或随便画的一个图标），复制到 `personal-blog/images/` 文件夹下。

::: warning 注意图片的真实格式
如果你的图片原本就是 `.png` 格式，把它重命名为 `avatar.png` 即可。

如果你的图片原本是 `.jpg` 或 `.jpeg` 格式，**不要直接把后缀改成 `.png`**——直接改文件名并不能转换图片格式，反而容易让人混淆。你有两种处理方式：要么用系统自带的「画图」软件打开它，点击「文件 → 另存为 → PNG 图片」存成真正的 `avatar.png`；要么保留它原本的名字（比如 `avatar.jpg`），但在后面写代码时，把代码里的 `images/avatar.png` 同步改成 `images/avatar.jpg`。

另外，练习项目后续会上传到公开网络，请使用虚构的昵称和简介，**不要**把身份证号、手机号、住址或私人照片等敏感信息放进代码里。
:::

## 边做边学：编写三个 HTML 页面

HTML 的全称是“超文本标记语言”。它的工作方式很直观：你写一段普通文字，然后用一对尖括号包起来的**标签（Tag）**把这段文字围住，告诉浏览器这段文字扮演什么角色。

大多数标签都是成对出现的，比如 `<p>这是一段话</p>`，前面的 `<p>` 叫开始标签，后面的 `</p>`（多了一个斜杠）叫结束标签。

下面我们按顺序写出首页、文章页和关于页。

### 第一步：搭建首页 `index.html` 的基础骨架

在 VS Code 左侧选中你刚才创建的 `index.html`，先把下面这段最基础的骨架代码敲进去（建议亲手敲一遍，注意所有尖括号、引号和斜杠都必须在**英文输入法**下输入）：

```html
<!doctype html>
<html lang="zh-CN">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>林晓的个人博客 - 首页</title>
  </head>
  <body>
    <h1>林晓的个人博客</h1>
    <p>记录我的编程学习与日常思考。</p>
  </body>
</html>
```

敲完后，按快捷键 `Ctrl + S` 保存文件（如果没保存，VS Code 顶部标签页的文件名旁边会有一个小圆点；保存后圆点消失）。

接着，去文件夹里找到 `index.html`，右键选择“打开方式”，用 Chrome 或 Edge 打开；如果默认应用已经是浏览器，直接双击也可以。你会看到页面上出现了一行大字“林晓的个人博客”和一行普通文字。

这段骨架代码是所有标准网页的固定开头，每一行都有明确分工：

- `<!doctype html>`：放在第一行，声明这是一个符合现代标准的 HTML5 网页。
- `<html lang="zh-CN">...</html>`：整个网页的最外层容器。里面的 `lang="zh-CN"` 叫做标签的**属性（Attribute）**，以 `属性名="属性值"` 的格式写在开始标签里，用来告诉浏览器和翻译插件：这个页面的主要语言是简体中文。
- `<head>...</head>`：网页的元信息区，不是后端程序。这里的内容用于描述文档，不直接作为正文显示。
  - `<meta charset="UTF-8" />`：规定文件使用 `UTF-8` 字符编码。如果不写这一行，某些浏览器打开页面时中文可能会变成一堆乱码。
  - `<meta name="viewport" content="width=device-width, initial-scale=1.0" />`：告诉手机浏览器按屏幕实际宽度显示网页，别把桌面网页强行缩小成看不清的小字（第 6 周做手机适配时会用到它）。
  - `<title>...</title>`：定义**浏览器标签页上的标题**。看一眼你浏览器最顶部的标签页，上面显示的就是“林晓的个人博客 - 首页”，当你收藏网页时也会默认用这个名字。
- `<body>...</body>`：网页的正文区域。要给读者看的文字、图片、链接都写在这里。比如 `<h1>` 表示最高层级的标题，`<p>` 表示普通段落（Paragraph）。标题层级表达内容结构，不只是字号大小。注意区分 `<head>` 里的 `<title>`（显示在浏览器顶部标签栏）和 `<body>` 里的 `<h1>`（显示在网页正文中）。

### 第二步：用语义化标签丰富首页 `index.html`

只用 `<h1>` 和 `<p>` 也能堆出网页，但当页面变复杂时，全部混在一起很难分辨哪块是顶部导航、哪块是正文、哪块是页脚。因此 HTML 提供了几个专门用来划分区域的**语义化容器标签**：

- `<header>`：页面或区域的头部（通常放网站名称、导航栏）。
- `<nav>`：导航链接区域（Navigation）。
- `<main>`：当前页面最核心的主体内容（一个页面只放一个 `<main>`）。
- `<article>`：一篇独立完整的内容（比如一篇博客文章）。
- `<footer>`：页面底部页脚（通常放版权说明或备案信息）。

这些容器标签本身不会给页面增加特殊样式，但能让代码结构一目了然。我们在哪个页面需要哪块区域，就自然地使用哪个标签，不需要在每个页面里强行把所有标签都凑齐。

现在我们来完善 `index.html` 的 `<body>` 部分，加入导航栏、站点介绍、近期文章列表和页脚。我们需要多用三个新标签：

1. **二级标题 `<h2>`**：用来划分主标题之下的章节（比如“近期文章”）。默认样式通常比 `<h1>` 小，但选择标题层级时，应按内容关系而不是想要的字号。
2. **无序列表 `<ul>` 与列表项 `<li>`**：`<ul>`（Unordered List）表示这是一个前面带小圆点的列表，里面的每一条内容各自用一个 `<li>`（List Item）包起来。
3. **超链接 `<a>`**：用来实现点击跳转。它最重要的属性是 `href="目标路径"`，比如 `<a href="post.html">第一周学习笔记</a>`，浏览器会把中间的文字变成可点击的链接，点击后就会跳转到同一文件夹下的 `post.html`。

把 `index.html` 修改为以下内容：

```html
<!doctype html>
<html lang="zh-CN">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>林晓的个人博客 - 首页</title>
  </head>
  <body>
    <header>
      <h1>林晓的个人博客</h1>
      <p>从零开始的 Web 前端学习记录。</p>
      <nav>
        <ul>
          <li><a href="index.html">首页</a></li>
          <li><a href="post.html">示例文章</a></li>
          <li><a href="about.html">关于</a></li>
        </ul>
      </nav>
    </header>

    <main>
      <h2>站点说明</h2>
      <p>
        欢迎来到我的个人博客。这里是我在网络部开发者计划中的练习项目，接下来半年我会每周学习一点新技术，并持续改进这个网站。
      </p>

      <h2>近期文章</h2>
      <ul>
        <li>
          <a href="post.html">第一周：我用纯 HTML 搭起了博客的第一版</a>（2026-10-01）
        </li>
        <li>第二周：给博客加上配色与卡片样式（待更新，暂无链接）</li>
        <li>第三周：用 Flexbox 排好顶部导航栏（待更新，暂无链接）</li>
      </ul>
    </main>

    <footer>
      <p>© 2026 林晓的个人博客 · 使用纯 HTML 构建</p>
    </footer>
  </body>
</html>
```

修改后，按 `Ctrl + S` 保存，回到浏览器按 `F5`（或点击地址栏左边的刷新按钮）刷新页面。你会看到导航列表和文章列表都已经显示出来了。

注意看“近期文章”列表：目前我们只写了一篇真实文章 `post.html`，所以只有第一条加了 `<a href="post.html">`，后面两条计划中的占位文章只写了纯文字，没有加 `<a>` 标签——不要给还不存在的页面制造死链接。

### 第三步：编写文章页 `post.html`

如果现在点击首页里的“示例文章”链接，浏览器会报错说“找不到文件”，因为我们还没创建 `post.html`。

在 VS Code 左侧面板点击「新建文件」，输入 `post.html` 并回车。

在这个页面里，核心内容是一篇完整的博客文章，所以在 `<main>` 里面，我们用 `<article>` 标签把整篇文章的标题、发布日期和正文段落包起来。同时，顶部 `<header>` 里的导航栏和底部 `<footer>` 保持与首页一致，方便读者随时跳回首页或去往关于页。

文章页完整代码统一放在后文的 [post.html（完整代码）](#post-code) 小节。可以先读完关于页的图片说明，再对照完整代码填写三个文件；每个文件写好后按 `Ctrl + S` 保存。

### 第四步：编写关于页 `about.html` 并插入本地图片

接下来在 VS Code 里新建第三个文件：`about.html`。

在这个页面里，我们要把刚才准备好的本地图片 `images/avatar.png` 显示出来，用到的标签是 `<img />`。

和 `<p>`、`<h1>` 不同，图片标签不需要包住任何文字，所以它没有结束标签，属性直接写在 `<img ... />` 里面。它有三个常用属性：

- `src="images/avatar.png"`（必填）：指定图片文件的位置（Source）。这里写的是**相对路径**——因为 `about.html` 和 `images` 文件夹并排放在 `personal-blog` 下，所以从 `about.html` 出发，先走进 `images` 文件夹，再找到里面的 `avatar.png`，中间用正斜杠 `/` 连接。
- `alt="林晓的像素风头像"`：图片的**替代文本（Alternative Text）**。本例需要填写能描述实际图片的文字，供屏幕阅读器等辅助工具使用；图片加载失败时，浏览器也可能显示这段文字。如果你放的是风景照，应把描述改成相应内容，不要照抄“像素风头像”。纯装饰图片另有空替代文本的处理方式，本周先练习有内容的配图。
- `width="120"`（可选）：由于本周还没用 CSS 控制图片大小，如果你找的原图分辨率很大（比如 2000 像素宽），直接放上去会撑满整个屏幕。加上 `width="120"` 可以让浏览器先把图片按 120 像素宽等比例缩小显示。

关于页的完整代码见后文的 [about.html（完整代码）](#about-code) 小节。

## 亲自验证与常见问题排查

写完三个文件后，去浏览器里把这几件事逐一验证一遍：

1. 在 `index.html` 点击导航栏的「示例文章」，能跳到 `post.html`；再点「关于」，能跳到 `about.html`；在任意页面点「首页」，能回到 `index.html`。
2. 切换页面时，观察浏览器最顶部的标签页标题（`<title>`），三个页面的标题会随之变化。
3. 在 `about.html` 页面中，能正常看到你放入的头像图片，而不是一个裂开的小图标。
4. 页面上的所有中文都能正常显示，没有乱码。

::: tip 浏览器能显示 ≠ 代码结构完全正确
现代浏览器有较强的容错能力，有些结构错误也可能被自动修补。所以看画面正常之后，还要回头检查代码，确认三个页面都正确组织了导航、主体和页脚，文章页的正文放在 `<article>` 中。不要为了凑齐标签而在其他页面强行增加 `<article>`。
:::

如果你在验证时遇到了问题，可以按下面的高频情况逐一排查：

- **改了代码，但浏览器里的画面完全没变**
  - 先看 VS Code 顶部文件名右边有没有小圆点。如果有，说明你还没按 `Ctrl + S` 保存。保存之后，必须切回浏览器刷新页面，修改才会生效。
  - 如果保存并刷新了还是没变，检查一下浏览器地址栏里的文件路径，确认你打开的确实是 `personal-blog` 文件夹下的那个文件，而不是之前在其他位置随手建的旧文件。
- **点击导航链接提示“无法访问此网站 / 找不到您的文件 (ERR_FILE_NOT_FOUND)”**
  - 检查三个 `.html` 文件是不是放在同一个 `personal-blog` 文件夹下（不要把其中某个文件误放进了 `images` 子文件夹里）。
  - 检查文件名拼写：比如文件叫 `about.html`，代码里是不是误写成了 `href="abuot.html"`；或者文件是不是因为隐藏了扩展名而变成了 `about.html.txt`。
- **`about.html` 里的图片显示为裂开的图标，旁边只显示了一行文字**
  - 旁边的文字其实就是你写的 `alt` 属性内容。注意：**写上了 `alt` 文字不代表图片修好了**，`alt` 在这里恰恰是在提醒你“图片加载失败了”。
  - 请检查三点：① 图片是否真的放在 `personal-blog/images/` 文件夹内；② 图片的完整文件名（含扩展名）是否与 `src="images/avatar.png"` 完全一致（比如实际文件叫 `avatar.jpg` 或 `Avatar.PNG`）；③ 路径里的斜杠是不是写成了反斜杠 `\`（网页路径统一用正斜杠 `/`）。

## 完成第一次本地 Git 提交

确认三个页面和图片都正常后，我们要用 Git 把这第一版成果记录下来。

你可以把 Git 提交理解成游戏里的“手动存档点”。每次完成一个阶段的任务，先挑选要保存的文件放进暂存区，再执行提交（Commit）。Git 记录的是这次暂存的内容，不会自动保存所有文件；提交后尚未暂存的新修改也不会包含在这次记录里。

### 1. 编写本周周志 `CHANGELOG.md`

按课程要求，每周提交前要在项目里记录两三句本周完成了什么。

在 VS Code 左侧面板（确保是在 `personal-blog` 根目录下，不要建在 `images` 里面）新建一个文件，命名为 `CHANGELOG.md`（`.md` 是 Markdown 文档格式），写入以下内容并按 `Ctrl + S` 保存。日期是示例，请换成你实际练习的日期，记录也按实际完成情况填写：

```markdown
# 个人博客迭代记录 (Changelog)

## v0.1 - 第 1 周（2026-10-01）

- 搭建纯 HTML 三页博客骨架：完成首页 (`index.html`)、示例文章页 (`post.html`) 和关于页 (`about.html`)。
- 使用 `header`、`nav`、`main`、`article`、`footer` 划分页面结构，实现三页导航互链。
- 在关于页引入本地头像图片 `images/avatar.png`；这一版代码将与周志一起进行首次 Git 本地提交。
```

### 2. 用 VS Code 源代码管理完成提交 {#vscode-first-commit}

本周直接用 VS Code 左侧的「源代码管理」完成初始化、暂存和提交，不需要先记住整套命令。VS Code 会调用电脑上安装的 Git，所以前面检查的 `git --version` 仍然需要通过。

::: tip 没登录 GitHub，也能开始
**Git 是电脑上的版本控制工具，GitHub 是托管代码的在线服务。** 初始化本地仓库、查看修改和创建本地提交，都不需要 GitHub 账号或登录。把仓库发布到 GitHub 是另一件事，本周先完成本地记录。
:::

**第一步：打开正确的项目文件夹**

在 VS Code 里选择「文件 → 打开文件夹」，打开自己创建的 `personal-blog`。左侧资源管理器应该能看到三个 HTML 文件、`images` 和 `CHANGELOG.md`。如果仍然停留在欢迎页，或只打开了一个 HTML 文件，先完成这一步。

如果这是你自己创建的练习目录，遇到工作区信任提示时可以确认信任。不要为了初始化练习而打开整个桌面或磁盘根目录。

**第二步：点击“初始化存储库”**

点击左侧像树杈的「源代码管理」图标，或按 `Ctrl + Shift + G`。在尚未初始化的项目中，选择「初始化存储库（Initialize Repository）」。如果弹出文件夹选择，确认是当前的 `personal-blog`。

找不到按钮时，可以按 `Ctrl + Shift + P` 打开命令面板，搜索并执行 `Git: Initialize Repository`（中文界面可搜索“Git: 初始化存储库”）。如果这个文件夹本来就已有仓库并显示更改列表，不必重复初始化。

初始化会在项目内建立隐藏的 `.git` 目录，用来保存版本记录，平时不要手动修改或删除它。**这一步没有上传文件，也没有建立 GitHub 远程仓库。** 默认分支名可能是 `main` 或 `master`，不影响本周练习。

::: warning 如果显示“当前没有源代码管理提供程序进行注册”
这条提示不能简单理解成“没登录 GitHub”。请依次检查：

1. 是否已经用「打开文件夹」打开 `personal-blog`，而不是停留在空窗口。
2. 在当前 VS Code 的终端执行 `git --version`。如果找不到 Git，先安装并彻底重启 VS Code；使用 WSL 等远程窗口时，要检查对应环境里的 Git。
3. 在扩展面板搜索 `@builtin git`，确认 VS Code 内置的 **Git** 扩展没有被禁用；检查设置中的 `Git: Enabled` 是否开启，再从命令面板执行 `Developer: Reload Window`（重新加载窗口）。无需另外安装 GitLens 才能初始化。
4. 仍有问题时，从命令面板打开 `Git: Show Git Output`，查看 Git 的检测信息；如果连这个命令都没有，应先检查内置扩展是否正常加载。

这些是排查路径，具体原因需要结合当前环境与日志判断，不要反复登录 GitHub 来尝试修复。可参考 [VS Code 官方排查指南](https://code.visualstudio.com/docs/sourcecontrol/troubleshooting)。
:::

**第三步：配置本项目的作者信息**

初次使用 Git，还需要设置提交记录里的名字和邮箱。这个步骤与登录 GitHub 无关，也不会给邮箱发送验证邮件。

在已经初始化的项目中，按 `` Ctrl + ` `` 打开终端，确认当前路径是 `personal-blog`。如果位置不对，用 `cd` 切换到你的实际项目路径，例如 `cd "D:\projects\personal-blog"`。然后把下面的占位文字换成自己统一使用的名称与邮箱，分别执行：

```bash
git config user.name "你的名字或英文昵称"
git config user.email "你的邮箱@example.com"
```

这里没有使用 `--global`，所以只配置当前仓库，必须在初始化之后执行。它们是作者信息，不是账号密码或 GPG 数字签名。以后公开提交时，邮箱也可能公开；有 GitHub 账号后，可以按需使用该账号提供的隐私邮箱。若配置已经正确，不必重复设置。完成后可以关闭终端，回到源代码管理面板。

**第四步：查看并暂存本周文件**

在「更改（Changes）」列表中，你应该能看到 `index.html`、`post.html`、`about.html`、`CHANGELOG.md` 和 `images/avatar.png`（按实际图片文件名为准）。新文件通常标有 `U`，表示未跟踪。点击文件可检查内容。

把鼠标移到每个本周文件上，点击旁边的 `+`，或右键选择「暂存更改（Stage Changes）」。文件会移到「暂存的更改（Staged Changes）」列表，这就相当于挑好这次要存档的内容。只选择本周练习文件，不要把无关文件一起加进去。

检查暂存列表里是否有这 5 个文件。保存文件只是写入磁盘，点击 `+` 只是暂存；它们都还没有创建提交。如果暂存后又改了文件，需要保存并再次暂存修改后的版本。

**第五步：填写说明并提交**

在源代码管理顶部的提交消息输入框中填写：

```text
完成第一周三页博客
```

然后点击「提交（Commit）」。本周选择普通的本地提交，不选「提交并推送」或「提交并同步」。若提示尚未暂存任何更改，先回去检查暂存列表，不要直接让编辑器自动把所有文件都提交。

若提示缺少 `user.name` 或 `user.email`，回到上一步配置作者信息后再提交，登录 GitHub 不能替代这个设置。若之前配置过签名并出现签名错误，应先核对自己的密钥配置，不要为了提交直接关闭已有签名要求。

**第六步：确认真的存好了**

提交完成后，本周文件应该不再出现在待提交的更改列表里。在源代码管理的「源代码管理图（Source Control Graph）」中，找到刚刚填写的提交说明，并打开检查记录里的文件。不同版本的布局可能不同；如果没找到历史视图，也可以在项目终端用下面两条只读命令核对：

```bash
git log -1
git status
```

第一条应显示刚才的提交说明和作者信息，第二条正常应显示 `nothing to commit, working tree clean`。如果还有文件列出，先检查它是否漏存、漏暂存，或是在提交后又被修改。

**第七步：先停在本地，不急着发布**

面板可能继续显示「发布分支（Publish Branch）」等按钮。这不代表本地提交失败，它只是提示当前还没有关联远程分支。现在不用点击。以后需要上传时，再通过「发布到 GitHub（Publish to GitHub）」按提示登录账号；本路线会在第 6 周讲解托管与上线。

文档站里的 Fork、PR 和签名提交约定针对向培训文档仓库贡献文章，本周的独立博客练习不要求这些操作。以上图形操作与命令行使用的是同一个本地仓库，原理可对照 [VS Code 官方入门教程](https://code.visualstudio.com/docs/sourcecontrol/quickstart)。

::: details 可选：同一套操作对应哪些命令？
这段用于对照理解，已经通过界面初始化和提交过的同学不需要再执行一遍。确认终端位于独立的 `personal-blog` 项目目录，初始化和作者配置的顺序如下：

```bash
git init
git config user.name "你的名字或英文昵称"
git config user.email "你的邮箱@example.com"
```

源代码管理里查看列表、点击文件旁的 `+`、填写说明并提交，分别对应以下命令。图片路径按实际名称调整：

```bash
git status
git add index.html post.html about.html CHANGELOG.md images/avatar.png
git commit -m "完成第一周三页博客"
git log -1
git status
```

`git add` 通常没有成功提示，要结合 `git status` 或界面中的暂存列表确认；`git commit` 保存的是暂存区的内容。
:::

### 选做挑战（学有余力时尝试，只用本周学过的 HTML）

- **在文章页增加有序列表**：无序列表 `<ul>` 前面是小圆点；如果把外层标签换成 `<ol>`（Ordered List，里面的每一项依然用 `<li>`），浏览器会自动在每一项前面标上 `1. 2. 3.` 的数字序号。试着在 `post.html` 里加一段用 `<ol>` 排列的“下周计划”。
