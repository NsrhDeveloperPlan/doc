# 学习计划与方向选择

本套教程旨在在实践中学习，我们从零开始开发自己的项目。从第 1 周的最小可用版本开始，你每周学习一个新概念或引入一个工具，直接改写手头的项目，并在代码仓库里留下一次提交记录。

对于前端和 Minecraft 模组方向，零基础的新生每周通常需要投入 5～7 小时，经过 24 个学习周和 2 个缓冲周（共 26 周），把一个初始半成品逐步迭代成可公开发布的完整作品。后端方向由于直接从接口开发与框架切入，默认你已经掌握所选技术栈对应语言的基础语法；如果从零起步直接选后端，需要先补齐语言基础，整体周期会相应延长。例如，未学过 Java 就走 Java 后端，大纲建议额外预留约 4～6 周，实际时间取决于基础和每周投入。

## 三个方向对比

计划提供三个独立方向。你可以根据自己的兴趣、对即时反馈的偏好以及当前基础做对比：

| 对比维度 | 前端开发 | 后端开发 | Minecraft 模组开发 |
| :--- | :--- | :--- | :--- |
| **主要学习内容** | HTML/CSS、JavaScript、Vue 或 React、组件库、TypeScript 与构建部署 | HTTP 接口设计、SQL 与数据库、登录鉴权、缓存与 Docker 部署 | Java 基础语法、NeoForge 或 Fabric API、数据生成、Blockbench 建模与世界生成 |
| **实践反馈** | 视觉反馈直接，修改代码后浏览器呈现页面变化 | 偏重数据流转与接口逻辑，初期借助接口调试工具查看返回结果 | 前 6 周在控制台跑文字逻辑，第 7 周起进游戏客户端看实际效果 |
| **基础要求** | 零基础友好，从浏览器和代码编辑器起步，同时学习 Git；后续按需使用本地预览服务 | 需具备所选语言的基础；与前端联调时最好有现成页面配合 | 零基础可入，前 6 周专门针对模组高频语法打 Java 基础 |
| **核心项目** | 个人博客，作为练习载体，逐周用新技术改造已有页面 | 博客后端 API，为博客提供文章、标签与鉴权服务 | 星辉工坊综合模组，逐步加入物品、工具、机器与生物 |
| **最终成果** | 一个用现代框架与组件库搭起、可在线访问的博客及 24 次迭代记录 | 一套容器化部署的接口服务，可替换博客的本地静态数据 | 一个可打包发布、带双语介绍的完整模组 |

## 如何选择你的起点

每周 5～7 小时的业余时间通常只够扎实走通一条路线，这边建议先选一个方向推进。

- **还没写过代码，想尽快看到画面反馈**：我们就可以选前端开发。你从最直观的网页标签写起，每学完一阶段（原生 JS、前端框架、组件库）就对同一个博客做一次升级，能清楚对比出每一阶段的技术到底解决了什么问题。
- **对页面样式没兴趣，更关心数据怎么存、接口怎么写**：选后端开发。你不必先学完前端才能开始后端；没有前端页面时，也可以用接口调试工具发送请求、查看 JSON 结果。如果你完全没有编程基础，需要先补所选语言的基础；也可以先完成前端前 12 周，再考虑切入后端，特别地： JavaScript 基础不能替代 Go、Python 或 Java 的语言准备。
- **平时常玩 Minecraft，想在游戏里做自己的物品、机器和生物**：选 Minecraft 模组开发。前 6 周会用文字版小任务带你过一遍 Java 核心语法，第 7 周正式进入游戏开发，不需要提前啃大部头教材。

### 后端的三个技术栈分支

后端方向的核心项目和四个阶段完全统一，但在具体实现上提供了 **Go + Gin**、**Python + FastAPI**（极简场景可用 Flask）和 **Java + Spring Boot** 三个分支。

你只需从中任选一栈走完，不要东一榔头，西一棒槌。后端的核心能力在于接口契约、数据表设计、鉴权与部署，这些思路跨语言通用。偏好编译成可执行文件、以较少的部署步骤运行服务，可以考虑 Go；未来想接触 AI 或数据分析，可以考虑 Python；对 Java 后端生态感兴趣，或者打算和 MC 模组共用语言基础，可以考虑 Java。三个分支的具体差异与选型建议，会在后端方向页详细展开。

### 关于 Java 后端与 MC 模组的复用

在本计划中，**Java 后端**和 **Minecraft 模组**可以共用 Java 语言基础，以及 JDK、IntelliJ IDEA 等工具的使用经验。两边也都会接触依赖管理，但具体项目使用的 JDK 版本、Gradle 或 Maven 配置，仍需按各自教程核对。

如果你两边都想学，可以先走模组方向的前 6 周把 Java 语言基础打牢，然后转去走完后端 24 周，最后再回来接着做模组的第 7～24 周。但要注意，模组的渲染、加载器事件与后端的 SQL、鉴权、容器化仍然需要分别学习。按这个顺序合计约 48 个学习周，另需安排缓冲、复习和环境恢复时间；以每周 5～7 小时的节奏，不应把它理解为半年内完成两条完整路线。

## 每周怎么学、怎么交作业

选定方向后，你可以这样做，把每周的 5～7 小时拆成三次使用：第一次花 2 小时左右看文档或跟练基础概念；第二次用 2～3 小时在项目上写出本周要求的代码；第三次用 1～2 小时排查遗留问题、整理记录。

为了防止你在某一周被卡死，教程对进度做了以下安排：

1. **任务分必做与选做**：每周的核心目标是跑通「必做」内容。完成本周列出的功能与自查要求、用 Git 留下提交记录、在项目的 `CHANGELOG.md` 里写下两三句本周改动说明，并留下一张运行截图，这一周就算达标。Git 提交可以先保存在本地，是否推送远程按当周要求执行。「选做」留给学有余力的同学，跳过选做不算落后。
2. **两个缓冲周**：第 12 周和第 18 周结束后，各设有一个缓冲周。如果前面落下了必做任务，或者连续两周推进吃力，就先放下选做，利用缓冲周把欠下的必做补齐、理顺已有代码；进度顺利的话也可以直接往下走。但无论如何，不要为了赶进度而省掉 Git 提交和周志记录，这些是你第 24 周整理作品时的直接素材。
3. **卡住 30 分钟就带着上下文求助**：写代码遇到报错很正常的~但如果自己长时间还是没能解决，就不要硬熬了。去搜索或向学长提问时，请提供**完整的报错文本**、相关代码、运行环境，以及**你已经试过哪些办法**；必要时附截图，不要只发一句“我的代码跑不通”。（~~这只能算一卦了~~）分享前检查是否包含密码、令牌或个人信息。（你也不想个人信息泄露吧）问题解决后，把报错原因和解决步骤顺手记进项目里的 `踩坑笔记.md`（这里是一个示例文件名，你可以自定义），免得下次再犯。

## 合理使用 AI 助手

写代码时可以用 AI 工具辅助，但用法要分阶段控制，别让它替你完成思考：

- **前两个阶段（第 1～12 周）**：把 AI 当成你的知心学长（或是学姐）。遇到看不懂的概念或满屏英文报错，可以请它解释原因，但项目里的代码需要自己动手写，并理解为什么这样写。
- **后两个阶段（第 13～24 周）**：熟悉基础套路后，可以让 AI 帮你生成重复的样板代码，但有一个标准：在执行 Git 提交之前，你必须能逐行讲清楚这段代码在干什么。看不懂的代码不要往项目里塞，塞多了就成~~屎山~~了（bushi）。

::: warning 模组方向特别提醒
Minecraft 不同版本及加载器的接口可能不同，AI 容易给出旧版本或者另一个加载器的代码，比如把 Fabric 和 NeoForge 混写。遇到报错，先核对项目、教程和官方文档的版本，以及使用的加载器。

准备向 Modrinth 发布时，还需重新核对[官方内容规则](https://modrinth.com/legal/rules)。截至 2026 年 11 月 12 日的核对结果：代码中有相当部分来自 AI，或资源、设计功能、项目页面等符合平台列出的 AI 使用情形时，需要作相应披露；以 AI 输出为主要或全部内容的项目不能公开发布，上传到项目页面的图片也不能由生成式 AI 创建或衍生。完成披露并不代表项目一定符合发布条件。
:::
